# PC 生词复习产品调整方案

日期：2026-10-20。状态：PC 第一版已本地实现并完成浏览器验收，尚未发布生产。本文保留改版前问题与分期目标；实际交付范围和验证以 `HANDOFF.md` 为准。

## 1. 当前行为与缺口

| 环节 | 源码确认的行为 | 产品影响 |
| --- | --- | --- |
| 进入复习 | 三项统计后同时展示模式、布局、筛选和搜索 | 缺少明确的本轮目标；界面结构待截图复核 |
| 作答 | 单词、释义和语境同时可见，直接按四档自评 | 未区分看过答案与独立回忆，不能据此计算客观正确率 |
| 排程 | 前端按评分固定安排 1/2/4/8 天 | 忘记也直接延至次日，无本轮重练；历史表现未参与间隔调整 |
| 掌握 | 最近一次评分为 good/easy 就归入已掌握 | 单次自评被表达为长期掌握 |
| 听写 | TTS 自动朗读，支持暂停和上下词，无答案输入 | 无听写判分与错词巩固，且违反仓库原声优先规则 |
| 保存 | 更新生词后另请求 activity，每次点击生成新的活动幂等键 | 两次请求可能部分成功，快速重复点击及失败重试存在重复计数风险 |
| 学习回访 | 现有每日 reviews 汇总，无独立复习会话 | 无法可靠恢复半轮学习、生成本轮结算或计算复习回访漏斗 |

依据：`VocabularyPage.jsx` 的 rate/speak/playDictationWord/filtered，`ReaderPage.jsx` 的 vocabPayload/saveWord，以及 `saas_workspace.py` 的 vocabulary/save_vocabulary/activity。未观察真实用户操作、无本轮截图，不作配色、间距或可访问性达标判断。

## 2. 建议的完整路径

阅读时收藏（保留来源句子）→ 今日复习入口（告诉我做多少）→ 一轮练习（先回忆再揭示）→ 薄弱词巩固 → 结算（真实完成与仍需巩固）→ 服务端安排下次复习 → 回到来源继续阅读。

商业路径：完成学习/查看反馈 → 用户实际需要更多 AI 解析或更多媒体内容 → 现有权益核验及升级弹窗 → 购买兑换 → 返回原复习会话继续。先提供可完成的基础学习价值，不在作答中插入付费拦截。

## 3. 页面结构与交互

### 今日复习：一个明确的开始入口

- 页面保留“生词复习”标题，一级切换“今日复习 / 生词本”；列表/网格偏好收进生词本。
- 主区展示真实待复习独立词条数、本轮计划数量和“开始本轮复习”；有未完成会话则改成“继续上次复习”。建议初始每轮 10 词，可选 5/10/20，参数后续验证。
- 区分逾期、今日到期和未练新词，计数互斥；到期优先，避免一次塞入全部积压。明确“本轮完成不等于全部清空”。
- 次区展示今日已复习独立词条和近 7 天复习天数，不重复占据三个等权大统计卡。预计时间在有真实测量后提供，否则只显示计划数量。
- 零生词：去书城阅读并解释收藏方式；今日完成：展示下一次已安排日期及“继续阅读”；筛选无结果：清除筛选。三种状态分开。

### 专注练习：每一步只有一个主任务

- 顶部展示本轮独立词条进度、当前模式、保存状态与暂停退出。题次和词条数量分开，错词重练不虚增“复习了多少词”。
- 首期采用词义回忆：只显示目标词和来源标题，释义、翻译和笔记先隐藏；可选择查看原句作为提示，记录是否使用提示。
- 点击“显示答案”后展示私人释义、原句及笔记，再给“忘记 / 模糊 / 记得 / 轻松”四档；明确属于自评，不显示“答对率”。
- 评分下方显示服务端给出的下次安排。忘记进入本轮稍后巩固队列，间隔其他题后再次出现；设置重练上限，仍未记住则结束时标记需巩固，不做无限循环。
- 本轮再次记住仍标记为“经巩固记住”，不计首次独立记住。掌握状态跨日评估。
- 提交时锁定该题按钮，失败保留答案/评分并用相同标识重试。刷新或退出后恢复到最后已确认的位置；退出不清除已提交成绩。
- 短暂提供纠正上一次评分的入口，纠正需服务端统一修正排程和汇总，不能靠客户端减一伪造撤销。
- 键盘 Tab/Enter 可完成流程，揭示答案后才启用评分快捷键；输入框内不触发全局快捷键。焦点、保存状态和错误需有可读文字，不只依赖颜色或 toast。

### 听写与语境练习：第二阶段

- 原声听写：播放来源音视频的原句，隐藏字幕及目标词；用户输入后按确定性规则判分，再展示原句、释义及重播。
- 只能使用有权访问且具备可靠起止时间的原始媒体。无单词级切片时称“原句听写/原句听辨”，不能把整句播放标为单词发音。
- 没有原声、时间戳或有效权限时明确原因，提供词义回忆或语境填空；不回退浏览器 TTS，不以付费保证修复缺失媒体。
- 输入支持跳过/我不知道；空值不算答对。大小写、首尾空格可规范化，词形/多个正确答案需明确规则，不默默接受任意近似答案。
- 语境填空使用已保存原句和目标词位置生成；缺失释义或词位的词条先补资料或跳过，不能展示空白试题或虚构释义。

### 结算：明确完成、薄弱点和下一步

- 展示实际完成的独立词条数、首次自评记得数、需巩固数和本轮有效练习时间。仅客观判分模式展示首次正确率及其分母。
- 区分“本轮完成”和“今日队列全部完成”。未完成会话展示“本轮已暂停，已保存 X 词”。
- 展示薄弱词清单和下一次复习日期；主按钮依据状态为“巩固本轮薄弱词 / 开始下一轮 / 继续阅读”。不把同日重练包装成长期掌握。
- “回原文”定位到对应官方或私人 React 阅读器的句子；权限失效时说明原因并提供合法路径，不打开旧 reader。
- 首期仅站内到期提示。外部邮件/系统提醒需要用户主动开启，另行评估，不默认发送。

### 生词本：负责管理，不承担主学习流程

- 支持词/释义/语境搜索、来源筛选、待学/待复习/巩固中/稳定记忆状态；列表展示来源标题及上次/下次安排，用中文替代 again/good 等内部值。
- 同一词在不同来源出现时可聚合浏览，保存各自语境；首期排程仍按现有词条身份，不贸然合并成绩。
- 可编辑释义/笔记、暂停某词复习、恢复复习；删除需明确范围并二次确认，暂停优先作为可逆操作。
- “稳定记忆”需跨日成功及间隔证据；阈值由产品确认并版本化。仅有旧 rating 的词条保留历史，不能自动宣传为已掌握。

## 4. 商业承接与边界

| 触发点 | 学习侧动作 | 商业承接 |
| --- | --- | --- |
| 卡在某个词 | 先提供已保存释义、原句和笔记；按需请求真实 AI 语境解析 | 只有服务端确认 AI 免费日额度触限时展示当前可升级商品 |
| 想增加原声学习素材 | 进入已有内容或导入路径，核验当前容量 | 容量触限时复用现有购买弹窗，解释具体额度，不另造复习收费项 |
| 完成一轮 | 展示真实结果及下一步 | 不强制弹购买；仅在有真实需求及对应已发布权益时提供轻量入口 |
| 购买/兑换返回 | 保留会话、题目和来源上下文 | 成功后刷新权益并允许继续原操作；失败/放弃也能返回练习 |

不改变 Free/进阶/Pro 定价或权益；不承诺“开通必能记住”、不使用假准确率或假进步。未来专项训练若收费，需另行确定能力、成本和权益版本，不能本轮直接上线销售。

## 5. 数据与接口实施要求（拟新增，当前不存在）

- 服务端管理复习 session：用户、模式、题目快照、当前位置、状态、排程版本；冻结本轮题目，避免评分后词条从客户端筛选列表消失导致跳题。
- 拟提供创建/恢复会话、读取当前题与进度、提交作答、暂停/结束和查询结算接口；按当前页加载，题量有限，复习统计由服务端聚合。
- 每题结果保存稳定 attemptId；同一 attempt 重试返回同一结果。服务端事务同时写作答事件、词条排程与每日活动，取代两次客户端写入。校验题目归属、会话版本和并发提交。
- 分开记录首次作答、提示使用、重练结果、自评/客观判分及版本；不将自评映射为客观正确率。日志和报表不写私人原句/释义。
- 所有新写接口保留认证、CSRF、租户隔离、幂等；服务端确认来源访问权限，不能靠客户端 bookId 或 payload 决定权限/排程。
- 统一工作区、复习页、学习记录的时区与到期口径；统计独立词条数、尝试次数、已安排数量，避免三者混用。
- 阅读器新收藏加入待学队列；编辑释义不能重置已有排程。兼容旧 due_at/reviews/rating，首次升级不虚构历史答题事件。
- 套餐兑换复用已有购买恢复逻辑，会话与商业操作分别校验，不能由前端宣称开通成功。

## 6. 分期及验证

第一期：今日入口 + 自评回忆练习 + 本轮重练 + 暂停恢复 + 结算 + 原文回跳；同时完成服务端排程、原子幂等提交与统一计数。这一期应先形成可完成的学习闭环。

第二期：有原声与时间轴的听写、确定性判分、语境填空、生词管理和真实周报；将现有 TTS 听写替换掉。

第三期：基于真实学习和触限数据评估现有升级入口、提醒和训练参数，不默认扩张权益或另起销售流程。

验收场景：首次无词、到期为零、大量逾期、缺释义/原声、官方/私人来源、权限失效、误点纠正、暂停刷新、跨设备恢复、断网重试、双击及双标签并发、兑换后返回当前题。不得拿正式账号制造测试成绩。

指标建议：复习开始人数、会话完成率、到期词条实际处理比例、首次客观答对率（只限判分模式）、到期后再次复习率；辅以 AI 触限后兑换及恢复操作比例。不将“打开页面”算复习，不把尝试次数当学习人数，不设未经验证的提升承诺。
