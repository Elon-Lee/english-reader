# 拾页 PC 商业化界面审查

日期：2026-10-19。对象：本地当前 React 版本；Chrome 1839×968；现有管理员 / Pro 账号。以下建议属于基于界面的产品判断，不是转化率实验结论。

## 总体判断

深绿、暖白和浅绿色已经形成较统一的视觉语言，适合拾页目前偏安静、专注的学习定位。真实产品截图、原声学习说明和明确的“不自动续费”值得保留。建议沿用这个方向，先提升首屏可读性、套餐可比较性和付费后的信任感，再增加视觉装饰。

当前主要问题：标题大而正文小，留白与任务密度不均；套餐重复条目挤压差异信息；部分内部数据直接进入用户界面。优先级 P1 表示建议先修，P2 表示后续体验优化，不代表生产故障等级。

## 1. 首页首屏：有品牌感，排版需优先修正（P1）

![首页首屏](/Users/x/Documents/english/.local/debug/product-design/commercial-audit-20261019/01-home-recheck.png)

- 优点：用户痛点与产品截图相邻，原始音视频、私人空间和学习积累有明确说明。
- 已确认：在当前宽屏下，“是终于读懂”被拆成两行，最后只剩“懂。”；标题计算字号为 92px。上方留白很大，正文和按钮相比标题显得弱。
- 建议：调整标题宽度、字号和中文换行，让“不是看过。”与“是终于读懂。”各成完整一行；缩小首屏无信息的垂直间隔。可以保留原口号，同时增加一句具体说明：“用原声视频逐句听读，把生词和难句留在同一个学习空间。”
- 当前会话显示“继续学习”是合理的；对新访客的方案建议是突出“免费体验一段”，其次“查看套餐”，但本轮没有验证未登录入口，不能说它目前缺失。

## 2. 产品介绍：叙事连贯，配图未充分证明价值（P1/P2）

![产品介绍](/Users/x/Documents/english/.local/debug/product-design/commercial-audit-20261019/08-product.png)

- 优点：按逐句学习、接续进度、看见积累来讲故事，比单纯列功能更易理解。
- 已确认：逐句阅读器展示图中，视频位置带加载转圈，右侧解释区为空；这是官网嵌入图片的内容，不能据此推断实时阅读器故障。
- 建议：换成完成加载、已有词义/句法结果的真实产品截图。突出一个句子和对应解释，减少缩小后的整屏细字；必要时提供可放大的截图或短演示。各段只保留一个主要结论。
- 配图应证明“我能怎样学会这一句”，不要只证明“页面里有这些面板”。

## 3. 套餐页：结构完整，选择逻辑不清楚（P1）

![套餐页](/Users/x/Documents/english/.local/debug/product-design/commercial-audit-20261019/02-pricing.png)

- 优点：三档并排、按钮底部对齐；30 天、不自动续费、免费长期可用都已明确。
- 已确认：免费和进阶同时有“推荐”标签及相近强调样式，无法识别主推项。Pro 缺少标签占位，名称、价格位置与另外两档不齐。
- 已确认：付费卡反复写“免费包含”；“公版书架收藏不限量”与“视频最多 20/100 个（公版 + 私人）”并列，需要用户猜测适用范围。
- 建议：只突出一个主推付费档，免费用“先体验”、进阶用“日常精读”、Pro 用“高频学习 / 大容量”；这些是拟议定位文案，需与目标用户确认。不要凭空写“最受欢迎”。
- 卡片先展示真正差异：AI 次数、视频/音频数量、空间、设备数、画质。共同能力放到卡片下方；付费条目改成“套餐包含”。不限量文案必须说明准确范围，不能更改真实权益。
- 三档名称、价格、首个权益和按钮对齐；减少顶部空白，使主要差异和操作更早出现。
- 价格建议主显“¥19 / 30 天”“¥49 / 30 天”。弱化复杂原价与红色折扣标签，若保留促销则补充真实条件。增加针对到期、释放容量、升级折算、付款后如何兑换的短 FAQ。

## 4. 购买弹窗：限制有效，反馈时机与措辞需改善（P1）

![购买限制状态](/Users/x/Documents/english/.local/debug/product-design/commercial-audit-20261019/03-purchase.png)

- 优点：购买与兑换在同一个弹窗说明；当前 Pro 账号不能购买较低档，按钮确实被禁用。
- 已确认：套餐卡仍允许点“购买 / 兑换”，进入弹窗才出现“暂时无法购买”；尚未提交兑换就显示“兑换失败且卡密未核销”。
- 建议：已登录时让套餐卡识别当前档位，直接显示“当前套餐”“续费 Pro”或“当前套餐高于此方案”。规则限制使用解释性提示，避免让人误认为网络故障或已经发生失败订单。
- 明确“云猫付款 → 复制兑换码 → 返回本页开通”，在跳转前说明由谁收款、如何返回、异常如何求助。若需要自动回填或自动开通，必须先确认真实支付集成能力。
- 本轮只查看弹窗，没有付款、发码或兑换。

## 5. 学习空间：主卡合理，日常任务还不够集中（P2）

![学习空间](/Users/x/Documents/english/.local/debug/product-design/commercial-audit-20261019/04-workspace-viewport.png)

- 优点：继续学习是最大卡片，封面与标题直观；周目标提供持续学习线索。
- 已确认：顶部导入按钮较突出；主卡没有呈现上次学习位置/剩余时间；同一本读物又在下面进度区出现。周目标的 0% 与大面积底色占用较多空间。
- 建议：第一屏组织成“继续上次内容 + 今日待复习 + 今天的小目标”。继续卡展示真实进度和原媒体位置；有真实数据时显示预计剩余时间；复习显示真实待复习数量。已有材料的用户将导入降为次要动作，新用户则提供挑选官方材料/导入自己的材料两条路径。
- 目标使用更温和且准确的下一步提示，如“本周从 10 分钟开始”，但不能静态假装完成目标。减少重复读物展示，将最近学习列表压紧。
- 管理员可见的运营入口不代表普通学习者也可见，本轮不把管理员菜单直接算作普通用户导航问题。
- 初次长截图侧栏出现窄化；正常视口复查宽度 248px、文字完整。该异常未确认，已排除出缺陷列表。

## 6. 书城：基础筛选明确，内容吸引力不足（P2）

![书城](/Users/x/Documents/english/.local/debug/product-design/commercial-audit-20261019/05-catalog.png)

- 优点：有搜索、分类、时长、句数、已收藏状态和真实操作入口。
- 当前本地数据仅展示两条材料，不能据此判断生产内容规模。当前卡片都是文字封面，标题在封面、标题行和摘要重复；“未分级”与收藏 0/阅读 1 等信息较显眼。
- 建议：视频优先用已存在的真实首帧；摘要用一句中文学习收益，标题保留两行；让资源类型、时长和经过核验的难度帮助选材。难度未知时不伪造分级。
- 若内容规模仍小，先做少量经过编辑的“从这里开始”推荐，不应硬填满卡片或捏造热度。低样本热度可降级到详情，把空间留给“这段材料适合谁”。
- “首页 · 书城”建议统一为“发现内容”或“书城”，与公开首页、学习空间区分。

## 7. 会员概览：当前状态可见，信息顺序不合理（P1/P2）

![会员概览](/Users/x/Documents/english/.local/debug/product-design/commercial-audit-20261019/06-membership.png)

- 优点：方案名、到期日、续费入口都可见。
- 已确认：大量会员变更历史排在实际用量之前；“不限次数”旁有空进度条，含义不清。
- 建议：顺序改为“当前方案/到期日 → 用量与剩余空间 → 续费 → 历史订单”。无限能力用文字或状态标签，不画 0% 进度条；已取消历史折叠或放独立页签。
- 当前 Pro 用户的主要操作可以直接写“续费 Pro”，避免模糊的“续费或升级”。

## 8. 用量与订单：存在明确可读性缺陷（P1）

![用量与订单](/Users/x/Documents/english/.local/debug/product-design/commercial-audit-20261019/07-membership-usage.png)

- 已确认：私人空间显示“507565206 / 20 GB 已使用”，分子没有单位；订单与侧栏显示 `commerce-pro-30-v2`，订单状态显示 `completed`，兑换来源重复。
- 建议：统一单位为“已用约 0.51 GB / 20 GB”（此示例使用十进制 GB；实际实现统一采用产品既定口径）；进度条与剩余量对应真实字节。
- 展示“Pro 会员 · ¥49 · 已开通”等业务名称，保留订单购买时的商品快照；内部版本号进入详情而不是主标题。补充真实订单日期、期限和必要编号，避免多条订单无法区分。

## 配色与排版的统一建议

| 用途 | 建议 | 对应证据 |
|---|---|---|
| 品牌与主操作 | 沿用现有深绿与 `#2F6F50` 主按钮，每个主要区域只突出一个动作 | 1、3、5 |
| 页面与卡片 | 暖白/浅中性色背景、白卡片；浅绿仅用于当前任务/推荐项 | 3、5、7 |
| 辅助颜色 | 周目标桃色降低面积或饱和度；红色优先表达错误，促销标记克制使用 | 3、4、5 |
| 文字层级 | 首页标题建议约 56–72px 起试；应用页标题约 28–36px；正文约 16px；以实际宽度验证中文断行 | 1、2、5、7 |
| 可读性 | 次级文字、筛选提示和星期标记偏淡，应进一步测量实际前景/背景对比度；不能仅凭截图宣称达标或失败 | 3、5、6、7 |
| 页面密度 | 公开页面保留叙事留白；登录后压缩页头空白，让第一屏看到更多可执行任务 | 1、5、6、7 |

这些是沿用现有品牌的建议，不是已实施的新设计系统。ui-ux-pro-max 的套餐比较与文字可读性搜索结果作为辅助检查项，未机械套用它给出的多色套餐方案。

## 建议实施顺序与衡量方式

1. 修可信度与明显排版问题：会员单位/内部码、套餐歧义与双推荐、首页断行、产品配图加载态。
2. 优化选择与行动：差异化套餐、当前会员状态按钮、学习空间的继续/复习任务。
3. 完善内容发现和首次体验。新访客链路需单独实测后再确定改法。

后续可衡量“首页到首次体验”“首次有效学习”“查看套餐到兑换完成”“次日继续学习”，先建立真实基线再比较改版，不把点击增加直接等同于付费或学习效果提升。

## 验证与边界

- 已检查上述八个页面状态的本轮截图与 DOM；正常视口验证学习空间侧栏，并剔除异常长截图。截图按编号存于本机目录。
- 不把后台/本地测试账号历史当成真实用户增长证据；不以官网内嵌旧截图证明当前学习器实时行为。
- 没有修改产品代码或套餐数据，没有发布、付款、兑换或开始移动端优化。
- 未完成：未登录与首次用户链路、真实资金闭环、完整阅读器交互、键盘/读屏和各 PC 宽度检查、线上对照。引用聊天不可读取。
- 验证通过：`npm run build:modern`、`npm run test:modern`、`npm run test:ui`（22 项）、`npm run check:js`、`python3 -m py_compile tools/reader_server.py`、`git diff --check`。构建保留大分包提示，不影响成功退出；这些检查不能代替设计建议实施后的浏览器验收。
