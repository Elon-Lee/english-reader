## 推荐方案（待用户确认，尚未部署）

- 一个仓库、一条集成主线；用短期功能分支实施，不建立长期国内/国际业务分支。
- 同一提交生成国内与国际两份 React 产物；共享阅读器、工作台、账号、内容管理组件。构建入口分别引用国内/国际站点模块，国内产物不打入商业页面与素材。
- 两个前端进程：国际 `127.0.0.1:5173`，国内 `127.0.0.1:5174`。保留历史 Cloudflare 回源端口，先核实云端配置再决定是否需要修改。
- 国内 Nginx 按已知域名转到 5174；主域提供 Astro 博客，learn 提供国内 React/API。国际 10ye.cc 经 Cloudflare 到 5173，提供完整商业首页、阅读应用及商业页面。
- 一套共享 API `127.0.0.1:8790`，一套 PG/Redis/媒体/验证码。共同业务只改一次；商业服务作为可控模块恢复。
- 国内入口和后端均拒绝商业路由；站点身份由入口覆盖注入并由后端校验可信来源和白名单，不能相信客户端自报站点。国际回调单独限制入口并验证支付渠道签名、金额和幂等。
- 账号、书目、进度、资源用量和有效权益按用户统一，不能按来访域名切换额度。旧受邀账号保留已有资源权益，新增国际免费/付费账号按统一模型计算；付费权益跨入口生效与原个人资源规则的具体兼容须随方案确认。
- 两个注册域使用各自会话 Cookie，同账号分别登录，不默认跨域免登录；验证码、验证邮件、重置密码与支付返回地址使用可信站点配置，不能直接拼客户端 Host。
- 同一发布包记录两个前端与后端版本、端口和域名映射；候选验证两入口，失败整体回退代码与配置。数据库仅做兼容增量迁移，保留数据与备份，迁移失败不盲目恢复覆盖正式库。
- 国际入口仍回源同一京东云源站，不应把 Cloudflare 接入等同于境外部署，也不承诺该架构能改变备案适用范围。
