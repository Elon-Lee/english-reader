# 普通 / 专注模式产品与视觉复查

> 实施更新（2026-10-20）：以下保留改前审阅证据；用户批准后，本地已完成普通/专注统一、密度/字体/语义色、查词动作和设置入口调整，并补验真实视频。完成状态、验收截图和限制以 `HANDOFF.md` 为准。

## 用户方向与本轮范围

- 用户明确取消“阅读 / 精读”区分，统一精读能力，只保留普通 / 专注两种呈现模式。该方向覆盖上一轮布局建议。
- 本轮为当前实现审阅和下一版规格，尚未修改产品源码。既有模式切换仍在，不能称新方向已落地。
- 使用 index → audit 和 ui-ux-pro-max；Chrome 沿用已登录隔离账号，1839×968，真实五句纯文本。未改收藏/笔记、未提交学习活动；结束恢复普通模式，放弃审阅片段。为比较统一精读基础，隔离账号 readerMode 设为 intensive。
- 以下截图均为本轮新采集并打开检查；布局/样式结论来自截图与可见 DOM 计算样式。无原音素材，未推断视频、录音与长文的实际表现。

## 1. 普通模式：功能清楚，句子卡片偏重

![普通模式](/Users/x/Documents/english/.local/debug/product-design/reader-modes-20261020/01-normal.png)

- 优点：句子和阅读位置清楚，工具按需打开，不保留空侧栏。
- 问题：每个单行句子约 107–109px 高，英文行高只有 37.8px，未显示操作时仍保留按钮行；卡片空白多、正文被切成独立块。
- 建议：普通模式定位为精读工作台。媒体、正文、当前学习工具可并排；没有选中内容时不占空栏。句子使用轻分隔，减少逐句白卡边界和空操作行；当前句显示明确操作，hover/键盘聚焦操作不推挤正文。工具常用动作保留文字，避免全部改成图标。

## 2. 专注模式：可用，但产品区别不足

![专注模式](/Users/x/Documents/english/.local/debug/product-design/reader-modes-20261020/02-focus.png)

- 观察：在无媒体、侧栏已关闭的材料中，切换前后正文、背景、顶部两行工具和底部导航几乎相同，仅模式按钮明显变化。按钮显示目标“普通模式”且高亮，容易混淆当前状态。
- 建议：专注模式定位为沉浸精读空间。取消常驻第二工具行；头部只保留返回、短标题、明确当前模式、必要保存/结束入口，设置放入次级入口。底部缩为紧凑进度/原音控制条。不要用定时隐藏方式让键盘用户失去控件。
- 正文成为一个连续纸面区域，句子语义和学习能力不变；不伪造来源段落。弱化编号与卡片边框，只对当前学习句/播放位置作轻标识，其他文字不降低透明度。
- 查词默认轻卡；句法和跟读临时展开，用完关闭回到原句。录音中不可自动收起。原视频默认收起画面，原音控制保留，用户可临时展开画面；不能因进入专注而中断原音或丢失进度。
- 退出专注恢复普通模式此前媒体位置、工具状态与阅读锚点；不覆盖普通模式固定偏好，不重置字号/行距、不丢失编辑、录音或活动草稿。

## 3. 专注查词：层级已较轻，仍有字号和主次问题

![专注查词](/Users/x/Documents/english/.local/debug/product-design/reader-modes-20261020/03-focus-lookup.png)

- 优点：词典真实可用，AI 未配置的失败提示已压缩；查词不改变阅读位置。
- 问题：“本句查词”实测 9px，来源原句 13px；词卡的主要实心按钮是“练这一句”，容易让收藏这个高频动作退居其次。此处是设计判断，尚无行为数据证明转化影响。
- 建议：词卡优先词义、发音、收藏；未收藏时将“加入生词本”设为主要动作，收藏后反馈一次再保留低强调状态。“练这一句 / 完整释义”为次级，定位原句按需要提供。标签至少 12px，中文解释 14–15px，来源句 13–14px。

## 两种模式的统一规格

| 维度 | 普通模式 | 专注模式 |
|---|---|---|
| 核心感受 | 工具齐备、有条理、便于拆解理解 | 安静、连续、以原文为中心 |
| 能力 | 查词、翻译、句法、跟读、收藏、保存 | 完全相同，按需出现 |
| 布局 | 正文 + 原媒体 + 有内容的工具区 | 居中正文，工具临时展开 |
| 句子呈现 | 轻分隔，当前句操作清楚 | 连续纸面，当前句轻标识 |
| 顶部/底部 | 完整学习控制 | 紧凑控制，保留明确退出和保存路径 |
| 媒体 | 原画面可见，适配左右/上下 | 原画面可临时展开，原音始终可控制 |
| 切换 | 保存当前布局状态 | 退出恢复原布局，不丢学习状态 |

不再添加“精读”模式按钮，也不把专注描述为泛读；两种模式仅改变工作空间的呈现方式。旧 readerMode 偏好需兼容忽略/归一，不应使旧 extensive 用户继续得到另一套体验；先核对系统设置中的 readerMode 使用位置再移除入口。护眼作为 Aa 下的外观偏好，独立于普通 / 专注。

## 布局、字体与颜色建议

- 删除“阅读 / 精读”工具条后合并快捷键提示到帮助入口，减少横向工具带。PC 先验收 1280×720 与宽屏，再处理移动端。窄 PC 不强塞三列，应将媒体上置或工具临时展开，以正文可读宽度为优先。
- 保留英文字体 Georgia 作为第一版，中文/UI 统一系统无衬线；目前正文 21px、1.8 行高并不需要一概放大。建议默认 20–22px、1.7–1.8，Aa 用户设置优先，两种模式共享；正文先试 680–760px，在真实长句中复核。以后若换 Source Serif 4，应做字体 A/B 视觉比较与本地加载验证，而非直接增加外部字体请求。
- 配色沿用暖白纸面、深绿操作、深墨色正文。候选语义：画布 #F4F3EF、纸面 #FAF9F5、正文 #26352C、辅助 #62746A、品牌操作 #315D49、轻选句 #EAF0E9。暖橙只用于明确的原音播放位置/批注，不给普通按钮各配一种底色；当前查词用浅绿细标识，语法分析角色色只在分析内容内使用。
- 当前句号 #839086 / 白底计算对比约 3.33:1；词卡来源句 #718077 / #FFFDF8 约 4.09:1；正文约 12.90:1。应优先加深小字，保留主要正文。候选辅助 #62746A / #FAF9F5 约 4.72:1。此为单色配对计算，非全站无障碍认证；hover、选中、护眼和遮罩合成背景仍需逐态检查。
- 专注的产品差异主要通过工具出现时机、纸面连续性与控制区密度体现；普通/专注共享字体家族和语义色，避免变成两套互不一致的主题。

## 建议实施与验收

1. 取消阅读/精读入口并兼容旧偏好；普通/专注状态名称明确。
2. 普通模式压缩空卡片与按钮占位；专注模式单独调整头部、正文、底部和临时工具。
3. 字体层级、小字对比、词卡动作主次统一；保留 Aa 和用户偏好。
4. 真实文本/音频/视频、1280×720/宽屏、普通→专注→普通，验证进度/播放/草稿/键盘焦点不丢；不把截图审阅当作音视频或录音验收。

本轮不修改产品源码；验证为浏览器三步审阅、计算样式与颜色配对检查。开发检查沿用仓库要求执行，具体结果见 HANDOFF。
