# 公开官网、商品套餐与个人支付交接

更新时间：2026-10-13（Asia/Shanghai）

## 目标

为拾页增加无需登录即可访问的公开产品官网和固定期限会员购买流程，满足面包多 Pay 的个人商户准入审查，同时提升真实用户的产品理解与购买转化。登录后继续进入现有 React 学习控制台，不重做控制台主体。

## 用户已确认的产品要求

- 由 Product Design 负责视觉方向、实现后的产品验收和质量把关。
- 官网要求简洁、大气，参考 Apple 官网的产品叙事方式：大留白、强产品画面、克制的层级、清楚的单一主行动。
- 必须使用真实产品配图并有适度特效动画；不能只靠文字或功能卡片堆砌。
- 文案应直接描述用户痛点，让访客快速理解拾页解决什么问题、如何工作、购买后获得什么。
- 未登录访问公开官网；登录后进入现有学习控制台。
- 产品名称、售价、权益和上下架状态必须可在运营后台维护。
- 后台必须支持产品版本管理；已下单用户和历史订单永久绑定购买时的不可变版本，后续改名、改价、改权益不得重写历史订单和会员权益。
- 暂定客服联系方式：QQ `289614546`。

## 已完成的准入与产品分析

- 面包多 Pay 可供个人申请支付宝、微信 JSAPI、微信 H5，但公开说明审核严格，重点核验真实产品、明确付费计划、经营场景、退款和投诉风险。
- 未备案域名阶段不申请、不展示微信 H5。微信 H5 的域名审核需要 ICP/经营性网站相关材料。
- 目标支付模式改为单次购买固定期限权益，不承诺自动续费或自动扣款。
- 建议首发四个付费 SKU：
  - 进阶会员 30 天：¥39。
  - 进阶会员 365 天：¥299。
  - Pro 会员 30 天：¥79。
  - Pro 会员 365 天：¥599。
- 付款成功必须采用本地订单 + 面包多 webhook + 主动查单双重核验；只有订单号、金额、商品版本和支付状态全部匹配后才自动开通。
- 同套餐提前续费从当前到期日顺延；免费用户从支付成功开始；已有套餐升级的首版规则建议人工处理，避免不透明折价。
- 套餐文案避免“充值、Token、虚拟币、余额、自动续费”等表达。产品定位是英语学习工具会员服务。
- “官方读物解锁”对外建议表达为“公版及授权学习材料使用额度”；“YouTube 导入”不作为核心销售点，对外表达为“在线视频学习导入”，并说明仅限用户拥有合法使用权的内容。

## Product Design 审查结论

当前页面不适合直接提交面包多审核：

1. 未登录根路径只有登录框，审核人员看不到产品、价格、交付、退款和客服。
2. 会员中心主文案仍出现 Paddle、API Key、webhook 和自动续费等内部实现信息。
3. 套餐以“月付/年付/自动续费”呈现，与面包多单次支付能力不匹配。
4. 购买按钮配置缺失时退化为“人工升级申请”，缺少标准订单确认页。
5. 当前退款页仍写“人工订单、不使用自动支付”，退款条件、响应时限和联系方式不明确。
6. 套餐弹窗部分禁用文字对比度偏低；后续还需键盘焦点、阅读顺序和响应式验证。

## 推荐的信息架构

- `/`：公开产品首页，不要求登录。
- `/pricing`：套餐、期限、权益和购买入口。
- `/purchase/:sku`：订单确认页，展示商品版本、期限、金额、交付、退款和协议确认。
- `/support`：QQ 联系方式、服务时间、订单问题说明和常见问题。
- `/terms`、`/privacy`、`/content-policy`、`/copyright`、`/refunds`：公开规则页面。
- `/app` 或登录成功后的现有工作台入口：进入当前 React 控制台。实际路由需要结合现有根路径生产架构确定，不能回退旧 `reader/index.html`。

公开首页建议叙事顺序：

1. 用户痛点：英语材料很多，但读不深、记不住、难以持续。
2. 核心结果：把自己的文本、音频和视频变成可逐句精读、跟读和复习的学习空间。
3. 真实产品画面：阅读器、逐句同步、生词与学习进度截图。
4. 三个重点场景：读懂、练熟、积累；不要展示完整功能库存。
5. 固定期限套餐。
6. 内容权利、隐私、支付交付和客服信任区。
7. 登录/开始使用 CTA。

## 数据模型要求

不要让后台直接修改已出售的 `plan_versions`。推荐增加商品层：

- `products`：稳定产品身份和运营分组。
- `product_versions`：不可变名称、描述、价格、币种、期限、权益快照、展示文案、状态、生效时间。
- `product_channels` 或 provider mapping：每个商品版本映射面包多渠道参数。
- `payment_orders`：必须保存 `product_version_id`、价格快照、权益快照、用户、外部订单号、支付渠道和状态。
- `subscriptions`/权益周期继续引用不可变套餐版本；开通时复制权益快照，避免后台改价影响历史用户。

后台操作规则：

- 改价格、期限或权益时创建新版本，不更新旧版本。
- 新版本发布后旧版本停止新售，但保留历史可查询。
- 产品可草稿、上架、下架；上架前校验价格、期限、权益、退款说明和渠道映射。
- 管理员写操作继续执行权限检查、CSRF、审计日志和幂等。

## 支付与退款流程要求

- 首发优先支付宝；微信内可展示微信 JSAPI；未备案阶段不展示微信 H5。
- 浏览器跳转成功不能作为开通依据。
- webhook 需验证来源并按外部事件/订单幂等；面包多 webhook 可能重复推送。
- webhook 到达后主动查单，核对订单号、金额、商品版本和最终支付状态。
- 前端轮询本地订单状态，并提供待支付、处理中、已开通、失败、关闭和退款状态。
- 重复支付、金额错误或未开通权益应支持全额退款。
- 建议规则：支付后 7 日内且未使用付费权益可申请全额退款；已消耗 AI、内容解锁、导入处理或存储权益时按使用情况审核。
- 客服暂定 QQ `289614546`；建议承诺 1 个工作日响应、3 个工作日给出处理结论。
- 退款通过原支付渠道退回；退款后相应会员周期终止或缩短，订单和审计记录保留。
